Done in 330c7d1 (plus e7a1ccf, a xarast-ui fix, and b35fb7b, the page fill in FrameJob), on branch worktree-agent-a193c011b72a4843c, rebased onto a04652d.

`xarast FILE.xar` opens the file and renders it. The composition root is `xarast_shell::viewer::Viewer` (the shell depends on xarast-ui, following arch §1 and phase-05 criterion 16). It wires the intent adapter, AppState, the egui Workspace (for layout and the canvas region), the RenderThread (CPU backend, woken through an EventLoopProxy) and a shell-owned egui+canvas painter. egui-wgpu 0.33 was not usable because it pairs with wgpu 27. The swapchain is now 8-bit non-sRGB.

Evidence: in a real Wayland window on the RTX 4000, all 59 corpus files open, render and capture via the new `xarast --screenshot out.png FILE.xar`. Launch-to-capture is ≤ 2.2 s except the three GradFilledShapes files (4–5 s, see T-0014). With no display, `--selftest-window` still exits 0 ("skipped"). Workspace: 810 tests pass, clippy -D warnings is clean, and cargo deny licenses reports ok.

Also fixed: reconfiguring a Suboptimal surface while it held its texture, which was a fatal wgpu error on Designs/Groucho2.xar. Known limit: the egui panels are drawn but receive no input until US-0002.
