Fixed in commit `432c607` (branch `agent/doc-perf-round`, based on `claude/xara-xtreme-rust-port-ktggmu` @ 345ddf2).

`Tx` now records the spreads each action can affect: the old parent of a detach, the new parent of an attach plus any spread inside the attached subtree, and the parent spread of a layer whose kind changes. A batch that changes structure falls back to the old full scan. `commit` repairs only those spreads, filtered to reachable ones. The invariant is unchanged because every document a Tx sees starts valid.

`dispatch/single_node_edit` at 100k nodes: **1.96 ms before (this run, load ~24) -> 101 ns after** (CI 100.97–101.23 ns, load ~5). undo 61 ns, redo 102 ns.

Tests: the undo/redo property test now also covers move, set-active and attach-a-spread-with-two-active-layers. New unit tests: `a_spread_broken_while_detached_is_repaired_when_it_comes_back` and `a_transform_touches_no_spread`. Disabling each tracking path makes a test fail. Workspace: 820 tests pass.

Note for the app-core owner: the comment at `crates/xarast-app/src/commands.rs:107` still says `Tx::set_kind` runs the repair after every call. That comment is stale.
