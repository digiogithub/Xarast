Fixed in commits `92007f7` (core) and `cf32847` (xar), on branch `agent/doc-perf-round`.

**Where the 644 ms went** (ProbeX16, 518k nodes). Neither `perf` nor `samply` is available, so this was measured with temporary instrumentation: parse ~95 ms, mapping ~130 ms, `DocumentBuilder::finish` ~200 ms (four whole-tree repair walks ~70 ms plus `validate()` ~129 ms), a node census 12 ms, a **second** `validate()` in `import()` ~127 ms, and dropping the analysis ~28 ms.

**Fixes:**
- `finish_with_report()` reuses the builder's validation report.
- `validate()` is now O(n): memoised cycle colouring, a SecondaryMap for the reachable set, no redundant seen-tags set, and the resource checks folded into the same walk.
- The tag index uses a multiplicative hasher.
- `Tree::attach` skips the ancestor and height walks for leaves.
- The builder records repair candidates at `node()` time.
- The importer moves decoded paths instead of cloning them.
- The node census iterates the arena when every node is reachable.

**Numbers** (median of 7 warm runs, 3 bench runs, load 8): ProbeX16 **644 → 329–343 ms** (budget 350; parse is 120–147 ms of that). Whole corpus **870–890 → 458–473 ms**. `builder/100k` 40–46 → 17.9 ms. This already includes the new quick-shape outline generation from T-0013 (~12 ms).

The margin is thin. The next wins are `Record.data` as a range into a shared buffer (870k allocations and a ~28 ms drop) and the depth walk in `attach`. Both are in `docs/memory/xar-import.md` finding 13. `fuzz_xar_import` (3.0M execs) and `fuzz_doc_builder` (3.6M execs) each ran for 5 minutes with no findings.
