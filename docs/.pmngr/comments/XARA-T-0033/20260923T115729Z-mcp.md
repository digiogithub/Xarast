Fixed in `cb9746a` + `e7ec12b`. `xarast-app` needs no change: `DisplayList::build` per strip picks it up.

- `cb9746a`: commands index into the scene's shared ops, so there is no per-op `PathRef` clone. `DeviceRect::enclosing` no longer calls libm, which roughly halves the scan.
- `e7ec12b`: the scene keeps a 40-byte culling entry per op (padded document bounds). A culled build reads only those for rejected primitives. Under an axis-aligned transform it rejects in document space (four compares) before transforming any corner, and only survivors read their op. A culled list's capacity is no longer sized to the scene. A test compares culled builds against the filtered full build, command for command.

`strip/build_1920x40_100000` (new criterion bench, `bulk` 100k): **0.26 ms**. It was 1.56 ms after `cb9746a` alone, and ~15–19 ms in your viewport bench before. Full builds are unchanged at 1.9 ms. I have not run `cargo bench -p xarast-app -- viewport` (it is not on this branch); please re-measure `viewport/zoomed/pan_draft` after merging. A build over a strip of a 224k-primitive scene should land around 0.6 ms.
