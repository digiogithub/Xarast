Done on branch `worktree-agent-a6eaf41d32e2d5067`: commits `65f00f1`, `417cca3` and `4a52a20`, with memory notes in `df93a99`.

**Root cause.** The bug was in the importer, not the walker. `TAG_CURRENTATTRIBUTES` holds the editor's *current* attributes, which the original makes current when it loads a file (`Kernel/rechdoc.cpp:1942-1966`). We were mapping them onto `DefaultAttrs`. The factory default fill is "no colour" (`Kernel/fillval.cpp:692-703`). SimpleSphere's current fill is black, so the unfilled frame came out as a black fill. The block is now counted and skipped.

**Repeat suspicion: confirmed.** Two things combined. The same block's `TAG_FILL_REPEATING` had become the default mapping. On top of that, the original ignores mapping values 0–3 on graduated fills and clamps them: only the "extra" repeat (4) tiles (`wxOil/grndrgn.cpp:2585`, `:2683-2740`, `:3967-3995`). `Tiling` gains `RepeatExtra`, and `paint.rs` now interprets the mapping per fill family. The same sweep found and fixed another bug: circular fills had a degenerate frame and painted nothing.

**Research.** The facts, with `file:line` references, are in `docs/research/01 §8.1/§8.3` and `02 §4.4`.

**Evidence.** Pixel probes in `crates/xarast-app/tests/fidelity.rs` fail when the bug is reintroduced. The workspace passes 896 tests. The `xarast-render` goldens are unchanged.
