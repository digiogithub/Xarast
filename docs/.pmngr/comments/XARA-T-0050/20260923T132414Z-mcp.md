Done on branch `worktree-agent-a5b15926d637f9263` (5 commits on top of d643be9): b2f3f5c core (RenderedFrame reports scene_epoch/covered/fresh/base; FrameJob::cpu_rescale), aeee286 render (GpuTileCache::valid), d043ed5 core (AppState::adopt), fc6ee08 ui (tile compositor, capability ladder, probe, RedrawAfter fix), 66e464e docs.

- Shell keeps each frame as 256² tiles per level (zoom + pixel grid) and composites the session's current view every present, so pan and Draft zoom show at input time. After a scroll only the fresh strips go up (plus partial tiles that have to start over at the trailing edge), about 320 KB per pan step. Draft zooms are skipped on the render thread; the Final at rest is a whole-frame render, cut into tiles when uploaded.
- Ladder: WGPU_ADAPTER_NAME, then high-performance, then the software fallback; WGPU_BACKEND is honoured (GL now works on Wayland). Canvas tier is GPU tiles, or CPU (compose_cpu over the same tiles plus one upload) when XARAST_RENDERER=cpu, when the cache cannot be created, or when GPU errors reach backoff. The status bar shows the tier and the adapter. Checked live on lavapipe, injected errors, a name with no match, and GL.
- Parity: a unit test shows the GPU and CPU tiers are byte-identical. Screenshots of ProbeX16 show identical canvases for {Intel, RTX} × {GPU, CPU}.
- Numbers, from input to presented on the live window with a 1796×1338 canvas, as p99: iGPU pan 1.3 ms / zoom 0.5 ms (GPU idle 5.5 / 2.8). Offscreen 4K iGPU to GPU idle, p99: pan 9.6 ms / zoom 5.8 ms. The CPU tier at 4K on the iGPU takes 35–41 ms (the T-0052 cliff). Full tables are in perf.md under "Pan and zoom end to end".
- Gates: fmt, clippy (workspace plus render --features gpu), 932 tests with the corpus, and ldd are all clean.
