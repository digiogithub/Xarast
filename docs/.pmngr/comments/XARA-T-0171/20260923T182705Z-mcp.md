Narrowed down: it is not specific to transparencies. `Designs/Fill Types simple.xar`'s bitmap row renders the "Xara" bitmap **upside down** in the CPU backend (every fill: plain, repeating, contone, duotone), while resvg draws the `.xarast` pattern upright (the pattern convention was verified against resvg, Inkscape and Chrome). So the CPU image sampling (`Paint::Image` and `LevelSampler`, both `y = v * height`) appears to be vertically flipped relative to the documented mapping (fill origin = image bottom-left, axis_y = top-left); the scope3/JagSS100 shadows are the same flip seen through a transparency. The `.xarast` render round trip is unaffected (both sides use the same renderer).
