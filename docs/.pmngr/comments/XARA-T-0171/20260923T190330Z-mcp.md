Fixed in 1bdaa0d (core) + 4545347 (docs), branch worktree-agent-adee9bb010a49a772, based on c104462.

Root cause: a bitmap fill's start point is the image's bottom-left (end = bottom-right, second end = top-left; `wxOil/grndrgn.cpp:3501-3521`, `4862-4865`, `Kernel/nodebmp.cpp:1210-1212`), but `xarast_render::Paint::Image` / `TranspSource::Image` sample v = 0 at the top row of the decoded (top-down) image. `xarast-app/src/paint.rs` passed the points straight through, so fills and bitmap transparencies were drawn upside down. The new `bitmap_frame` starts the frame at the top edge (affine and perspective). Renderer untouched.

Regression: `crates/xarast-app/tests/bitmap_orientation.rs` (synthetic 2x2 DIB: plain fill, bitmap transparency, mirrored tiling); all three fail on the old mapping.

SSIM vs resvg on the .xarast SVG (8x8 grey, before -> after): Fill Types simple 0.844 -> 0.880, scope3 simple 0.926 -> 0.959, JagSS100 simple 0.969 -> 0.995, WATCH 0.980 -> 0.991, Spitfire 0.850 -> 0.958, TestBitmapFill 0.985 -> 0.999. No golden changed. The mirrored tiles, contone and duotone tiles are the right way up too (checked against resvg and in the real window). Workspace tests: 1323 pass.
