## Report (branch worktree-agent-a0d029cdfb3258815; commits a0e8490 core, 036172b ui, 5e78334 docs)

**IME (T9.4.7).**
- `Viewer::ime_request` turns the IME on exactly while egui's text field or the canvas's text caret wants it. `set_ime_cursor_area` gets the caret box (`Session::ime_cursor_area`, from the new `Tool::text_caret`) plus the canvas origin.
- `ShellEvent::Ime` goes through the viewer's `ImeState`:
  - a preedit becomes `Intent::TextPreedit(Some(Preedit))`;
  - a cancel becomes `TextPreedit(None)`;
  - a commit becomes `Intent::TextInput(Insert)`, which follows the normal typing-burst rules.
- While the IME is composing, keys are dropped.
- The preedit is drawn in the story through the new `Preview::text`: the walker splices the text in (`text::splice_text`). The underline, the highlight for the selected segment and the caret come from a spliced `CaretMap`. None of this touches the document.

**Clipboard (T9.4.8).**
- While a text caret is up, Copy/Cut/Paste act on text:
  - Copy with a text selection keeps a styled copy in `AppState::text_clipboard`, holding the character text slots plus fill/line colour. Colours are dropped when pasting into another document. The plain text goes to the system clipboard.
  - Copy or Cut with a collapsed caret does nothing, so the story object is never cut.
- `EditCommand::PasteText` (label "Paste", also works at a pending caret, where it creates a new story) writes attributes only where the pasted text differs. `EditCommand::CutText` has the label "Cut".
- Text from other apps is pasted as plain text. If the clipboard holds our own object SVG, the paste is refused with a status message.
- No new dependency.
