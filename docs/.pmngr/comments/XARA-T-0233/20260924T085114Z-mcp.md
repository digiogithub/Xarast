## Report — SVG export embeds fonts or writes outlines (branch `worktree-agent-ab43a0cf8dd7e9d59`, NOT merged with the working branch yet)

Commits: `01e95d4` (WOFF2 + `@font-face` through the shared mapper), `efe6087` (`TextOutput`, `--text text|outlines`, outline fallback), `6dc4b52` (docs).

- **`AsText` (default):** the same WOFF2 subsets `.xarast` stores (shared `xarast_text::embed` layer, same `fsType` check), inlined as `data:font/woff2;base64,…` behind one `@font-face` per face; each run's `font-family` chain names the faces its characters are drawn with. `FontNotEmbedded` is now reported only for a face that was not embedded. `Capabilities::embeds_fonts = true`.
- **`AsOutlines`** (`SvgOptions::text = TextOutput::Outlines`, CLI `--text outlines`): the seam decided is `ExportSource::text_as_outlines(all)` — the application converts stories to shapes on a *copy* of the document (`xarast_app::convert::text_as_outlines`, the convert-to-shapes geometry = the walker's) and the mapper writes that copy. No `<text>`, no `@font-face`, no `FontNotEmbedded`.
- **fsType:** a story drawn with a refused face is converted to outlines in `AsText` mode too, and reported (`FontNotEmbedded`, reason says outlines).

**Acceptance (TextDesigns + TextCurve, system fonts, 72 dpi, resvg vs our PNG):** `--text outlines` gives SVGs with no `<text>` and mean |Δ| 0.55–2.17 (TextCurve 0.57, was 3.06 as live text); live text with embedded fonts 0.45–3.55; corpus SVG median 0.70, `export-check --limits` 0 failures. Tests: `xarast-app/tests/font_embedding.rs` (`svg_export_embeds_woff2_subsets_and_outlines_the_refused_face`), `xarast-cli` `text_output_is_a_pdf_and_svg_option`. `xtask svg-render`/`export-check` load an SVG's embedded fonts into resvg (usvg ignores `@font-face`).
