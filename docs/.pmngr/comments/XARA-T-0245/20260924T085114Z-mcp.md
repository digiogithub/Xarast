## Report — outline fallback for PDF and SVG export (branch `worktree-agent-ab43a0cf8dd7e9d59`, NOT merged with the working branch yet)

Commits: `0416a42` (PDF), `efe6087` (SVG + `ExportSource::text_as_outlines`), `6dc4b52` (docs).

- **PDF:** a face whose `OS/2.fsType` forbids embedding is never subset; its runs stay the walker's glyph outlines (the same geometry convert-to-shapes uses, so they render identically) and the report carries `FontNotEmbedded` once per family.
- **SVG export:** `xarast_app::convert::text_as_outlines(doc, fonts, all = false)` converts, on a copy of the document, exactly the stories drawn with a refused face (`text::story_refused_faces` lays each story out and checks its faces), with `xarast_doc::convert_story_to_shapes` — group + one path per run, `was-text` and the source text in the model. The document itself is untouched (asserted).
- **Note on the acceptance criterion:** `xarast:was-text` cannot appear in an *exported* SVG: the interchange dialect removes every `xarast:` attribute by construction (export.md invariant). The outlines are there, plain SVG paths, rendering as the text did.
