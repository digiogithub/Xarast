Report (branch worktree-agent-a675e321d193b6b59, on top of 0b7f21a; not pushed or merged).

**What shipped.** Text on a path now follows its curve in the `.xarast` base SVG and in SVG export. Each character gets its own `x`/`y`/`rotate` from `PathFit::cluster_transform`. This is the tracker body's second option. `<textPath>` is not used.

**Why not `<textPath>`.** I built it, measured it and dropped it:
- resvg 0.45 loses the path after the first child element inside a `<textPath>`. Stories with several runs, or with a kern-only first run, came out straight.
- One `<textPath>` per run fixes resvg (3.47), but Inkscape 1.2 then draws nothing sensible. It ignores `x` lists inside `<textPath>`, and when a `<text>` has several `<textPath>` children every multi-line or multi-run story on TextCurve disappeared.
- The per-character version draws on the curves in both resvg and Inkscape 1.2. It needs no reader change and no derived `<defs>`.
