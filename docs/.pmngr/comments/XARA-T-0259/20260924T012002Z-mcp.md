## Report (ready for review)

**Design.** `xarast_app::save::SaveJob` now carries `text: Option<Placer>`, set to `Some(svg_text::placer())` by default (the process's shared font service), and passes it to `prepare_save` / `prepare_resave` in `SvgOptions::text`. Text placement happens while the SVG is serialised, **on the save thread**, over the restored document. `save_job` on the UI thread only clones an `Arc`. File › Save, Save As, a save before closing and the periodic autosave therefore write the same `document.svg` as `xarast-cli convert`. `SaveJob::without_text_placer()` is used only by `AppState::emergency_shutdown`, because the signal path must not wait for font enumeration. Only Xarast reads a recovery snapshot, and its reader ignores placement.

**Bytes.** New test `xarast-cli/tests/app_save.rs` covers the 59-file corpus with pinned fonts. For every file, an app save (`save_job(Document).deterministic().without_thumbnail()`) is byte-identical to `convert_one(--deterministic)`: 59/59 match, and 2 of those files turn characters along a path. TextCurve's SVG has `rotate`. File › Save with the thumbnail adds only `thumbnail.png` and writes the same `document.svg`. Autosave writes the same SVG at deflate 1. `xarast-app/tests/save.rs` now compares the snapshot path against a direct save that uses the placer: 59/59.

**Cost.** Measured with `examples/save_probe.rs` (release build, ext4, load average about 3, 3 runs). The probe now has a no-placer row.
- ProbeX16 UI thread: 30–38 ms, unchanged.
- ProbeX16 save thread: 970–984 ms with the placer and 965–991 ms without, so the difference is within noise. With the thumbnail it is 1.05–1.07 s.
- TextCurve: 7–8 ms against 5 ms without the placer. The package is 22 271 B against 6 046 B.
- Rotated: 6–8 ms against 4 ms.

**Gates.** All five pass (fmt, clippy, tests 1715 passed / 0 failed / 1 ignored, deny, build --locked).
