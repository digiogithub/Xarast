Report (branch `worktree-agent-a557a1711e373accb`; commits ca742a1, 51a6765, 53c8bc9, aacd29e).

**T10.3.6: `NodeBitmap` default attributes.** `xarast-doc/src/bitmap_place.rs` has `default_bitmap_attrs`, `bitmap_node_centred` and the `PlaceBitmap` command. The facts in `Kernel/nodebmp.cpp:997-1055` show that a new bitmap object gets three attributes of its own: no line colour, no fill colour and zero line width. It does not get a bitmap fill. `research/02 §8.6` said otherwise and is corrected. The object draws its own image.

**T10.3.8: placing by drop and by paste.**
- `Intent::ImportImage { path, at }` handles a drop and `Intent::PasteImage { width, height, rgba }` handles a clipboard picture, both in `xarast-app/src/place.rs`.
- The image is decoded once under the default limits. PNG, JPEG and GIF bytes are kept as they are; any other format is stored as a lossless PNG with its DPI.
- The size is the natural size, `px × 72000 / dpi`, and the object is centred on the drop point or in the view.
- Each placement is one step ("Import Bitmap" or "Paste") and the new object is selected. A file that is not an image gets a notice and changes nothing.
- Shell: a drop places image files at the drop point and still opens other files as documents. Paste uses the clipboard's picture only when the text there is neither our own copy nor SVG and no text caret is up.
