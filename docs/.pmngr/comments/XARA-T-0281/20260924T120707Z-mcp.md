## Report (branch worktree-agent-aceb5c4b6760b91d4, not merged, not pushed)

Commits: 08edfaa render (Draft level by footprint), 5b04d5f render (MissingLevels::Substitute, image_damage, proxy kept on eviction), c0c0572 render (backend policy setter), 55baefc core (render thread: helper thread plus Final repair), 454b3dd core (DecodedImages per-document cache), 162c6c2 docs.

**Design**
- Draft `Nearest` samples the pyramid level trilinear would start from (⌊log2 footprint⌋ at 2× or more, otherwise the base) and pins only that level. Draft output changes only for images minified 2× or more. No golden moved. Final and export are unchanged.
- `CpuConfig::missing_levels`: both presets keep `Materialise`, which is byte-identical. With `Substitute`, a level that needs its base back is drawn from the best resident smaller level, and the image is stamped (`substitution_tick`, `ImageRef::substituted_since`). Eviction reduces the base down to the proxy first, so a substitute always exists.
- Render thread: `CpuFrameRenderer` uses `Substitute`. The worker sends stamped images to a helper thread that calls `ImageRef::rematerialise`. It adds `image_damage` to `Kept::inexact`, so the Final is published as not exact. When the helper is done, the worker re-runs the job under its own generation (generations now come from a shared atomic counter). That repair goes through the normal `Plan::Repaint`/`FrameReuse::Repainted` path, so the tiles update. The repair samples with `Materialise`. It can therefore read a base synchronously, but only when the budget is too small to hold one frame's images.
- Cache: `Session` owns `DecodedImages`, keyed by the `Arc` addresses of `pixels` and `original` (the entry holds those `Arc`s), plus the declared size and the budget. Build_scene, CLI export, headless renders and the save thumbnail all share it. Damage still compares ImageRefs by store or content; this is tested.
