**Resolved by explanation, plus a gate (XARA-US-0061, branch `worktree-agent-a16f32544bfa1b76a`).**

- **The app already keeps it off the critical path.** `xarast-shell/src/main.rs` calls `fonts::prewarm()` before it creates the viewer. The viewer opens documents only once its window exists, about 300 ms later, so fontconfig enumeration (~40 ms) has finished by then.
- **Headless there is nothing to overlap.** I added a prewarm at `xarast-cli` start, measured it and reverted it. Spitfire's first open went 45.9 → 44.8 ms (medians of 5–7, load ~90), which is noise. The import that the enumeration would overlap takes only ~5 ms. Re-opens in the same process take 4–6 ms.
- **Gate:** `spitfire-first` (nightly) runs `xarast-cli bench open --doc Designs/Spitfire.xar` and checks `first_ms` (open + first paint): measured 100–108 ms, limit 200 ms scaled by calibration. The numbers are in perf.md, "CI gates".
