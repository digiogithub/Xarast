**Design** (`crates/xarast-render/src/effect_cache.rs`, render.md "The effect layer cache", new invariant 25):
- `CpuBackend` owns an `EffectCache`, on by default. The key for each outermost effect is: its push..pop scene ops (compared by op equality), the ramps and images they name (compared by content with the damage diff's own rule, `damage::ramp_tables`/`same_image`), the effect and view transforms bit for bit, the viewport, quality and dpi, and the pass's coverage left edge, band height, SIMD pin and luma weights. A change under an effect changes the key in exactly the cases `scene_damage` reports it. No explicit invalidation.
- The draw area is not in the key. A layer is trusted only over the `keep` area it was rendered for (invariant 23). A lookup assembles the pieces from up to 8 layers per key and renders only the uncovered part, so the render thread's `Final` columns and later repaints reuse each other's layers.
- Nested effects are not cached separately. Results drawn from a substituted image (`MissingLevels::Substitute`) are not stored.
- Memory: the cache has its own 128 MiB ceiling (`DEFAULT_EFFECT_CACHE_BYTES`, `set_limit(0)` turns it off). It is LRU, but a layer the current frame uses is never evicted, so a frame that does not fit cannot cycle its own layers out.
- Pans: decided not to serve them from the cache. The coverage origin is fixed by the view (invariant 23) and rows sit on the band grid, so a translated layer is not guaranteed to match a recomputed one. `scroll_surface` already moves the on-screen pixels, and the exposed strips were never computed. Zooming back to a bit-identical view does hit.

**Timings** (`xarast-cli bench render --whole`, 1080p, release, load 13–16, run interleaved with the old binary). This is a new flag: plain `render` now measures pixel reuse, see perf.md.
- Groucho2: median 26.7 → 6.2–6.7 ms; first frame unchanged (~33 ms).
- feathers.xar: median 42–46 → 3.3–3.6 ms.
- One-shot `xarast-cli render` output is unchanged, and the PNGs are byte-identical.
- New gates: `render-feathers` (pr, limit 12) and `render-groucho2` (nightly, limit 16). The old binary fails both.
