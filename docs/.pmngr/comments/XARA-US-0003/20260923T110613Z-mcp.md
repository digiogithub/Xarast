Implemented in `e883f44`. `accesskit_winit 0.29.2` is behind the default-on `accessibility` feature in `xarast-shell`. `cargo tree` resolves exactly one `accesskit` (0.21.1, shared with egui) and one `winit`, and `cargo deny check licenses` is ok. The adapter is attached before the window is first shown. Activation, deactivation and actions arrive as `ShellEvent::Accessibility*`. The viewer turns on egui's AccessKit output and publishes the tree through `ShellCtx::update_accessibility`, with the root named after the window title and the toolkit set to `egui`.
**Real AT-SPI check** on the live COSMIC session, with `IsEnabled` set to true for the run and then restored to false, using python `gi.Atspi` against `xarast BLUECAR.xar`:
- The app `xarast` (toolkit `egui`) shows a frame "BLUECAR.xar — Xarast" with 39 nodes, 29 of them labelled: "Hide layer Main layer" check boxes, "Main layer, visible, unlocked" list items, the colour panel buttons, the status labels and "Document canvas: BLUECAR.xar, 107 % zoom".
- An AT-SPI `click` action on "Hide layer Main layer" turned the node into "Show layer Main layer", so the action round-trip works.
Headless tests also cover this: there's no tree until activation, and a screen-reader Click hides the layer.
