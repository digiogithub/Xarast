Implemented in `a4745dc`. A detached `xarast-settings` thread runs `ashpd` `Settings::receive_color_scheme_changed()` under `pollster` with `futures-lite::StreamExt`, and posts each change as `PortalEvent::ColorSchemeChanged`. It is separate from `xarast-services`, which blocks inside an `rfd` dialog. `PortalService::start_with_waker` wakes the event loop after every answer, dialog answers included, which fixes a latent bug: a parked loop used to notice a portal answer only on the next input event.
Verified on a real D-Bus without touching the maintainer's theme. Under `dbus-run-session`, a fake `org.freedesktop.portal.Settings` (python Gio) emitted `SettingChanged` light, then dark, while `xarast BLUECAR.xar` ran. The app logged `desktop colour scheme changed` followed by `following the desktop colour scheme` for each flip, about 0.2 ms apart, so the idle loop was woken. The live COSMIC portal was not flipped. New unit test: `an_answer_wakes_whoever_is_waiting`. Workspace total: 845 tests passing.
