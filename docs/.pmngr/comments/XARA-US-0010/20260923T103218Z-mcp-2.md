**3/5 — Document model re-measured** (`cargo bench -p xarast-doc --bench doc`, synthetic 100 002-node document, two runs):

| Operation | Budget | Measured | Verdict |
|---|---|---|---|
| `preorder` 100k | ≤ 1.5 ms | **1.07–1.08 ms** | passes (it was 2.09 ms on the container) |
| random `Tree::get` | ≤ 5 ns | **5.10–5.67 ns** | at budget. The figure includes the bench's own index hash and modulo, so the `get` itself is under |
| `walk_render` 100k | ≤ 2.0 ms | 0.87–0.92 ms | passes |
| **undo** of a single-node edit (undo only) | ≤ 1 ms | **0.28 µs** | passes |
| redo | ≤ 1 ms | 0.10 µs | passes |
| **dispatch** of that edit (new bench) | — | **1.04 ms** | ⚠ the edit itself now costs about 1 ms |
| `AttrResolver` warm / cold | 30 ns / 2 µs | 18.9 ns / 0.87–0.92 µs | passes |
| `AttrStack` push+pop | 20 ns | 12.1–12.9 ns | passes |
| builder 100k | 150 ms | 40–46 ms | passes |
| `canonical_digest` | 30 ms | 4.1–5.7 ms | passes |
| `snapshot()` | 25 ms | **43–80 ms** | **1.7–3.2× over** (unchanged finding) |
| `compute_bounds` cold | 12 ms | 7.6–8.1 ms | passes |

**Regression found:** the old `undo/single_node_edit` bench timed dispatch and undo together, and it went from 0.27 µs to 1.13 ms. The whole cost is in `Tx::commit` → `keep_one_active_layer`, which walks the **entire tree** (`preorder`) on every commit to find spreads, so every edit costs O(document size). The bench is now split into `dispatch/` and `undo/`. Undo meets the budget, but interactive editing at 100k spends about 1 ms per command on this scan. It is not fixed here (not this story's scope). Suggested fix: keep a list of spreads, or only check the spreads the transaction touched.
