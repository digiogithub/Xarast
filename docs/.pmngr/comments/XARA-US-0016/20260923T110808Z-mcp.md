Display-list build fixed (render side), branch `worktree-agent-a83f377a34c9927e1`:

- `cb9746a` render: make DisplayList::build linear by sharing the scene's ops. The cause was that `DrawCmd` was 384 B and cloned path/paint/style/transparency: at 100k the list came to 38 MB, which is over glibc's mmap threshold, so every build page-faulted a fresh mapping and every drop touched 200k cold Arc counters. `DrawCmd` is now 32 B of indices (the scene ops are shared through an Arc, and device transforms and mapped paints sit in side tables). `DeviceRect::enclosing` no longer calls libm floor/ceil.
- `67579ff` render: cut per-primitive overhead in the CPU backend.

| bench (reference machine, loaded, criterion median) | before | after |
|---|---|---|
| display_list/build_20000 | 1.116 ms | 0.332 ms |
| display_list/build_100000 | 19.5 ms | 1.95 ms (budget 3 ms) |
| full_frame 1080p 100k (interactive) | 49.1 ms (44.7 recorded) | 22.8 ms (budget 25 ms) |
| full_frame 1080p 20k | 9.94 ms | 8.17 ms |

Golden images are unchanged. The AttrResolver cache item mentioned in the body belongs to xarast-doc/app, so I did not touch it.
