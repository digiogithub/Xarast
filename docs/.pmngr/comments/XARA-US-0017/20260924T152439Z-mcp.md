### Criteria
1. **`RampMapping::Sin` honoured.** Done. `xarast-render` gains `RampEase` with `build_ramp_eased`, `build_transparency_ramp_eased` and `RampCache::intern_eased`. The change is additive: the old API delegates, and the easing is part of the cache key. The parameter is eased before the profile, the same order as `Ramp::sample`, so the canvas now matches the SVG export. Finding: the original never draws a sine mapping, and its `.xar` writer refuses it (`Kernel/fillattr.cpp:18639-18660`), so no imported file carries one. Pinned by ramp unit tests and a canvas probe against `Ramp::sample` (±3).
2. **Perspective `p2`/`p3` ordering.** Confirmed from the source, not from a golden image. `wxOil/grndrgn.cpp:2540-2560` passes Start, EndPoint2, EndPoint3, End for a linear fill (Start, End, EndPoint3, EndPoint2 for the others). EndPoint3 is the far corner (`Kernel/fillval.cpp:1513`), so `p2` is (0,1) and `p3` is (1,1), which is what `paint::perspective` already does. **A golden against the original is impossible:** no `.xar` fill record carries perspective corners, and the corpus has 0 perspective fills (they exist only inside the 129 perspective moulds, which are Phase 13 live objects). Pinned by a pixel test: a parallelogram perspective draws as its affine twin (±1), and a trapezoid's far edge lies where `p3` puts it.
3. **When `Tiling::Repeat` becomes `RepeatHq`.** Already decided (app-core decision 31): only `Tiling::RepeatExtra`.
4. **`ClipViewMode::Outside` supported.** Done. The walker builds an inverted path: the frame around the other children minus the clip path, through `xarast_geom::boolean` under the ClipView's rule, pushed as a non-zero clip. There is no renderer change. **This also fixed a bug: no ClipView had ever rendered.** The walker popped the clip before the group, the scene underflowed and the render failed. The clip child is no longer painted in outside mode.
