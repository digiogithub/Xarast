**Built**
- T10.6.1 — `xarast_doc::photo`: `PhotoOp` (crop, orient, levels per channel, gamma, brightness, contrast, saturation, greyscale, `Unknown { kind, raw }`) and `PhotoOps` on `BitmapNode::photo_ops`. The chain is a set with one canonical order; `normalise` sorts it, keeps the last value per kind and drops neutral ops. `hash` is the same whatever order the ops were set in. Unknown ops freeze the chain: no normalise, no edit, not rendered, written back verbatim. `SetPhotoOps` is one undo step. With the master's size, a crop keeps the kept pixels in place on the page and a turn swaps the object's size about its centre. `Session::set_photo_ops` is the "Adjust Photo" entry point.
- T10.6.2 — the cached evaluator. The walker paints a derived image keyed by (master, chain hash). It is evaluated once and registered under the pixel budget with a re-evaluating expensive source, and filed in `DecodedImages` so the export and thumbnail walkers reuse it. When the epoch moves, pairs that no attached object uses are pruned from both caches, and the registry slot is reused through the new additive `ImageRegistry::replace`.
- T10.6.3 / T10.6.4 — `xarast_image::photo`. Geometry is plain copies. Each channel gets one fused LUT, rounded once, and the channel mixes run after it. A 24 Mpx B+C+G chain takes 66 ms and matches the fused table pixel for pixel (criterion 13). `xarast_io::photo` is the only translation from chain to recipe, and a test checks it against the model's placement geometry for 8 orientations × 3 crops.

- Export: PNG/JPEG/WebP/PDF render the derived image. SVG bakes a PNG of the adjusted pixels and reports `Simplified`; without a baker it reports `NotRendered`.
- Damage: an adjustment repaints only its own object (tested next to a second picture), and undo gives zero damage against the earlier frame.
