**Report: branch `worktree-agent-a16f32544bfa1b76a`, 4 commits on top of 838e939** (ac6b432 core, 5fd2d88 pkg, 642cf99 pkg, 8f80d3c docs).

**What was built**
- `xarast-cli bench <scenario>` (A1/A2/B2/B5): scenarios calibrate, startup, open, save, undo, render, pan, zoom, export and leak. They run on synthetic documents (`--nodes`) or on a real file (`--doc`). All are headless and CPU-only. Each prints one JSON object with medians, p95/p99, `first_ms` and peak RSS (`VmHWM`, reset after set-up).
- `cargo xtask perf [--tier pr|nightly]` (A4/A6/C2) reads its gates from `xtask/perf-budgets.txt`. Noise control:
  - A calibration workload (st/mt) runs before every scenario, and time limits are scaled by `max(1, calib/ref)`.
  - Every value is a median or percentile.
  - Margins are documented.
  - A breach is measured twice before it fails.
  - A failure prints the metric, the limit, the % over, the calibration factor, the reference number and the first run's value.
- CI: the `perf` job in ci.yml runs the pr tier on every push. The new `perf-nightly.yml` runs every gate with the corpus. Both upload the results JSON. No new dependencies (serde_json was already a workspace crate), no apt packages, no GPU.

**Gates: 12 per push, 27 nightly.** Full table with limits, budgets and numbers is in perf.md, "CI gates".
- Per push:
  - startup (process ≤ 400 ms, frame, RSS)
  - open/save/render/pan/export at 10k objects, plus RSS
  - undo ≤ 1 ms and edit at 100k objects
- Nightly adds:
  - open/save/render/pan (fit p95 ≤ 16, p99 ≤ 24, zoomed)/zoom at 100k objects
  - peak RSS ≤ 1.5 GB
  - leak (200 cycles)
  - ProbeX16 open/save, Spitfire first open
